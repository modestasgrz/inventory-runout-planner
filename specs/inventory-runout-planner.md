# Inventory run-out planner

Status: approved | Date: 2026-11-09 | Owner: Modestas

## Goal
A purchasing manager today keeps a spreadsheet to answer "what runs out, when, and what do I reorder within this month's budget". This app replaces that spreadsheet for a generic retail/wholesale catalogue: real public monthly demand for 36 products plus clearly labelled synthetic stock data, a what-if scenario sidebar, and a ranked reorder plan where every number can be traced to its formula and inputs.

## In scope
- Build script: download UCI Online Retail II (sha256-checked), clean it, select 36 products, write the committed derived demand CSV; seeded synthetic stock data written to a committed CSV.
- Pure calc core (Pydantic models + pure functions, no Streamlit): forecast, do-nothing projection, run-out month, limiting factor, reorder suggestion, ranking, budget funding, KPIs, CSV export tables, number formatting.
- Streamlit app: pages Overview, Forecast, Scenarios, Reorder plan, Methodology; shared sidebar with scenario inputs, 5 presets and Reset; KPI strip on every page; 4 CSV downloads; dark navy theme (one theme file, `.streamlit/config.toml`, one CSS file, one Plotly template).
- Input validation with clear messages; synthetic-data notice, planning date and dataset attribution on every page.
- `requirements.txt` exported from `uv.lock` for Streamlit Community Cloud.
- Playwright screenshot tool (1280 and 1440 px) and a README with screenshots, method and attribution.

## Out of scope
- Uploading your own product or stock data, editing products in the app, saving scenarios between sessions.
- Multi-order plans (the plan is the next order per product), multi-echelon / multi-warehouse, supplier price breaks, currency conversion.
- Statistical forecasting models (ETS, ARIMA, ML), confidence intervals.
- Deploying to Streamlit Community Cloud (later owner step), making the repo public, any outbound action.
- Any LLM or external API call at runtime.
- Aligning the theme with the sibling app `retail-kpi-dashboard` (owner proxy does it after both builds).

## Acceptance criteria

Months are indexed 1 = 2011-12 (Dec 2011), 2 = 2012-01, … Toy product defaults: `unit_cost=2.00, stock_on_hand=100, lead_time_weeks=4, moq=50, capacity=400, inbound_qty=0, inbound_weeks=0, group="Gifts & small goods"`. | DEC-08 | Lead months `L = ceil((lead_time_weeks + delay_weeks) × 7 / 30.44)`; an order placed at the start of month m arrives at the start of month m + L. Existing inbound arrives at month `1 + ceil((inbound_weeks + delay_weeks) × 7 / 30.44)` (inbound_qty 0 = no inbound; after the horizon = flag `Inbound arrives after horizon`). Projection per month: available = opening + inbound; shipped = min(demand, available); unmet = demand − shipped; closing = available − shipped. Run-out month = first month with unmet > 0. | PART-A |
| DEC-09 | Reorder: safety units(t) = round half up(safety_months × forecast(t)). Trigger n = first month (1…H) with do-nothing closing < safety units(t) or unmet > 0; none → no order. Order month = max(1, n − L), arrival a = order month + L. Available at a = do-nothing opening(a) + inbound(a). Need = forecast(a) + forecast(a+1) + forecast(a+2) + safety units(a) − available at a. Room = capacity − available at a. If room < MOQ → no order, flag `Capacity blocks order: room X < MOQ Y`. Else qty = min(max(MOQ, need), room). cost = round(qty × unit_cost, 2). Value at risk = total do-nothing unmet over the horizon × unit_cost. Rank all orders by (run-out month index, or H+1 if none; value at risk descending; stock_code ascending). Fund in rank order: funded if cost ≤ remaining budget, else not funded and the next order is still tried. Limiting factor: no run-out → `none`; else arrival > run-out month → `lead time`; else no order (capacity) → `capacity`; else not funded → `budget`; else `stock`. With-plan projection = do-nothing + funded qty at arrival (if ≤ H). Cover months = stock_on_hand / mean(forecast 1…H) (mean 0 → infinite); > 6.0 → flag `Overstocked: X months of cover` (1 dp); infinite cover (stock > 0, mean forecast 0) → flag `Overstocked: no forecast demand`. `order_now` = the product's do-nothing run-out month index ≤ lead months + 1 (the order must be placed now). Products at risk = count of products with `order_now` (the 12-month projection itself is unchanged). Earliest run-out = among products with a run-out month, the smallest one; ties by value at risk descending, then stock_code ascending. Entry point: `planner.run(data: PlannerData, scenario: Scenario) -> ScenarioResult`. | PART-A |
